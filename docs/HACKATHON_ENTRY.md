# Briefstamp: a short path through the evidence

**For freelance website handoffs:** turn an agreed requirement into a reviewed check, an observed result and a portable report. A passing check proves its specific assertion; it does not certify the entire website.

## Try it in three minutes

Follow the [judge guide](JUDGE_GUIDE.md): open `#demo`, choose **Audit this live site**, review and approve the labelled checks, audit the actual owned homepage and download its report. Five assertions passed and one judgment stayed unverified. Changing only the heading expectation produced one real failure; both audits were saved and read through Tiger.

The [October 16 live-site proof](evidence/hosted-website/2026-10-16T09-10-55Z/receipt.json) used a real Google-hosted Gemma proposal through Mastra, then explicit verifier approval and Chromium observations. One native HTTP 200 attempt reported **389 input / 296 output tokens**. The wrong-heading control failed and both audits round-tripped through Tiger. [Historical failures and contract fix](GEMMA_LIVE_SITE.md) remain visible. The optional model route never supplies browser scripts or bypasses approval.

## What the open models actually did

- **Gemma:** on October 16, native `gemma-4-26b-a4b-it` proposed six checks for the actual owned homepage in one HTTP 200 attempt, reporting **389 input / 296 output tokens**. Two Mastra steps generated and validated the output in an isolated worker (189.04 MiB maximum RSS). Unapproved execution returned 409. After explicit verifier approval, Chromium observed **5 passed / 0 failed / 0 blocked / 1 unverified**; changing only the heading expectation produced **4/1/0/1**. Tiger returned both exact audits and the failed heading through lexical retrieval. [Current receipt](evidence/hosted-website/2026-10-16T09-10-55Z/receipt.json). Earlier October 15 healthy/broken/restored synthetic evidence and provider failures remain separately labelled in [the proof history](PUBLIC_GEMMA.md). This is agent verification, not human customer acceptance.
- **Tinker:** real Qwen3.5-4B LoRA used **69.55% fewer input tokens** than few-shot on the same 24-request synthetic cohort, implying **55.52% lower inference-only cost** at recorded uncached rates. This is an estimate, not billed savings: reference agreement fell from 23/24 to 22/24 and latency increased. Training plus one-day checkpoint storage would amortize after 87 comparable requests; that projection was not executed. Zero human-validated examples.
