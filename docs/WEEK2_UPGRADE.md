## Implementation

Tinker has a separate frozen experiment and a nonrefundable single-training-reservation guard. Its new summary compares the old few-shot, old LoRA and eventual new LoRA without rewriting the original run. It reports agreement, inappropriate abstention, input/output tokens, latency, false passes and conditional cost per successful synthetic handoff. Provider-billed actual cost remains unavailable without attributable billing evidence.

The optional Mastra gate binds generated unapproved checks to an immutable run digest. Approval flags can change; assertion edits require replacing the plan. Visitor approval resumes the actual SDK workflow. A second native suspension waits for the external Chromium result, allowing the SDK child to exit before Chromium starts. A final SDK process restores the same run and validates the actual results. Snapshots live only in web-process memory. Old audit receipts remain intact when a visitor changes variant or regenerates a rules/Tinker plan.

The optional Temporal path wraps real Gemma selection, Tiger retrieval, SerpApi search and Gemma summary in activities. Existing Tiger reservations still limit a run to 2 model calls and 1 search. Provider requests have no automatic retry; one controlled Temporal retry happens before dispatch. Completed phases are cached, and an uncertain earlier dispatch fails closed. The total deadline stays 90 seconds. The existing authenticated operator alone can request the controlled restart; anonymous visitors cannot inject it. Session-scoped UI status comes from actual workflow history/query data.

Production now starts compiled server JavaScript with a 96 MiB V8 old-space limit. SDK workers run in isolated bounded processes and exit between memory-heavy phases. SSR chunks stay beside their entrypoints so existing sibling worker paths remain valid. `/health` reports the validated `RENDER_GIT_COMMIT` as `sourceCommit` when Render supplies it. Both new features remain **disabled by default**.

Existing reservations and quotas were not raised or reset: Gemma 2 generations per visitor session, up to 3 physical calls reserved per generation, 12 reserved physical calls/hour; browser 4 audits/session and 24/hour; existing judge grant/session limits; the original Tinker 2-request reservation and its cumulative remainder. An expiry refresh or redeploy is never a new allowance. The existing hosted ledgers and prior uncertain/completed reservations must be reviewed and carried forward before deployment.
